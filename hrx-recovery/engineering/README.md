# HRX-OS AI研发组织

> 本组织目录当前应用于 `hrx-recovery` 独立恢复工程（Recovery 0.7）。它不表示原 V19.6.10 源码已进入本仓库，也不改变原工程的版本与数据库边界。

## 组织结构

- **首席架构师 / GPT-6**：总体架构、技术决策、业务逻辑、跨组协调、最终研发验收。GPT-6 是技术决策角色，不是 GitHub 人类账号或可替代业务Owner的审批人。
- **系统架构组**：领域边界、服务拆分、API契约、架构决策记录、跨模块一致性。
- **前端研发组**：React、Vite、页面交互、无障碍、真实数据状态与错误呈现。
- **后端研发组**：Java、Spring Boot、API、领域规则、事务、幂等和审计。
- **数据工程组**：PostgreSQL、Flyway迁移、RLS、索引、数据治理、备份恢复。
- **安全工程组**：OIDC/JWT、RBAC、最小权限、职责分离、文件安全和威胁建模。
- **测试工程组**：TDD、单元测试、集成测试、浏览器E2E、回归和缺陷复现。
- **DevOps组**：Git分支、GitHub Actions、构建、部署、监控、依赖和供应链。
- **业务专家组**：工程、采购、生产、质量等业务规则、角色场景、验收证据。
- **统一质量验收与交付中心**：汇总测试、代码审查、发布门禁、版本清单、SHA-256和交付记录。

## 工作原则

1. 先读当前模块、API、数据库迁移和既有测试，再决定新增或修改。
2. 先定义验收条件和失败场景，再按TDD实现。
3. 不伪造企业OIDC、ERP/MES/PDM、病毒库或生产数据连接。
4. 不自动批准角色、采购、付款、库存过账或质量放行。
5. 所有新数据库结构通过递增Flyway迁移；不得改写已发布迁移。
6. 每个PR必须关联任务、说明影响范围、附测试证据和回滚方式。
7. 未运行的测试标记为 NOT RUN；环境缺失标记为 BLOCKED；不能写成 PASS。
8. 本目录是专业分工和责任边界，不代表GitHub组织团队已创建。当前仓库属于个人账号，GitHub Team需组织账号才能建立。
